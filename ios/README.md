# MadeHappen for iPhone & iPad

The native app is a **Capacitor** shell around the existing React web app. There
is no second UI codebase: `frontend/` is built once and loaded by a native
WKWebView, so every feature you ship on the web ships here too.

Everything in this document from step 2 onward **must run on a Mac with Xcode** —
the iOS toolchain does not exist on Linux/CI without a macOS runner.

---

## Layout

```
capacitor.config.json     app id, name, and which folder holds the web build
package.json              Capacitor deps + the ios:* scripts (repo root)
frontend/                 the React app — the app's entire UI
  src/native.js           status bar, splash, haptics, safe areas (no-ops on web)
ios/                      generated Xcode project (created by `cap add ios`)
  App/App.xcodeproj       open this in Xcode
  App/App/Info.plist      permissions, display name, orientation
```

`ios/App/` is generated by Capacitor on first setup, not written by hand.

---

## 1. One-time: what you need

- A Mac with **Xcode 15+** (App Store, free)
- **CocoaPods** — `sudo gem install cocoapods`
- An **Apple Developer account** ($99/yr) — required to test on a physical
  device and to submit to the App Store. The simulator works without one.

---

## 2. First-time setup

From the repo root:

```bash
npm install                 # Capacitor CLI + plugins
npm run build:web           # builds frontend/ for mobile (see "API URL" below)
npm run ios:add             # generates ios/App — run once, then commit it
npm run ios:open            # opens Xcode
```

In Xcode: select **App** → *Signing & Capabilities* → set your **Team**. Xcode
will provision automatically.

---

## 3. The API URL (important)

On the web, the app calls `/api` on its own origin. Inside the native shell
there is no such origin — the web build runs from `capacitor://localhost`, so
the API base **must be an absolute URL baked in at build time**:

```bash
cd frontend
REACT_APP_API_URL=https://your-production-domain/api npm run build:mobile
```

`npm run build:web` from the root does this for you as long as
`REACT_APP_API_URL` is exported in your shell. Build without it and the app will
launch but every request will fail.

The server already allows the native origins (`capacitor://localhost`,
`ionic://localhost`) in its CORS config — see `backend/app.py`.

> **Why `build:mobile` and not `build`?** The web build has a `postbuild` step
> that replaces `index.html` with the marketing homepage and moves the app to
> `app.html`. The native shell loads `index.html` directly, so a plain `build`
> would ship an app that opens the marketing page. `build:mobile` skips the
> swap.

## 4. Everyday workflow

After any change to the React app:

```bash
npm run ios:build     # rebuild web → copy into the native project → open Xcode
```

Then press ▶ in Xcode. Or, to skip Xcode:

```bash
npm run ios:run       # build and launch on a simulator/device
```

`npx cap sync ios` alone copies a fresh web build and updates native plugins.

---

## 5. iPad

The same build serves both — the React layout is already responsive, and the
timebox's sidebar layout benefits from the wider canvas. Two things to set in
Xcode under *General → Deployment Info*:

- **iPhone + iPad** as targeted devices
- **Requires full screen** unchecked, so Split View and Slide Over work

Test at least one narrow (Slide Over) and one wide (full screen) iPad size —
those exercise different breakpoints in the web layout.

## 6. Icons and splash screen

Place a 1024×1024 PNG (no transparency, no rounded corners — iOS masks it) and
a splash image, then generate every required size:

```bash
npm install -D @capacitor/assets
npx capacitor-assets generate --ios      # reads assets/icon.png + assets/splash.png
```

The splash background is set to the app's dark chrome (`#1c1209`) in
`capacitor.config.json`, so there's no white flash on launch.

## 7. Shipping to the App Store

1. Bump the version in Xcode (*General → Identity*): **Version** is what users
   see, **Build** must increase on every upload.
2. *Product → Archive*, then **Distribute App → App Store Connect**.
3. In App Store Connect: screenshots (6.7" iPhone **and** 12.9" iPad are both
   required), description, keywords, support URL, and a privacy policy URL —
   `PRIVACY.md` in this repo is the source for that page.
4. Fill in **App Privacy**. The app collects an email address and the user's
   task content; declare account data and user content, linked to identity.
5. Submit for review.

### Review notes worth planning for

- **Thin wrappers get rejected.** Apple's guideline 4.2 targets apps that are
  just a website in a shell. The native touches in `src/native.js` (haptics,
  status bar, splash, safe areas) help, but the strongest defences are offline
  behaviour and genuinely native features — push notifications for due tasks, a
  home-screen widget, or Siri Shortcuts for adding a task. Consider adding at
  least one before the first submission.
- **Sign in with Apple** becomes mandatory if you ever add third-party social
  login (guideline 4.8). Email/password alone does not trigger it.
- **Paid tiers must use Apple's in-app purchase** for digital content, at 15–30%
  commission — Stripe checkout inside the app will be rejected. The usual
  approach for the first release is to ship the free tier only and keep upgrades
  on the web, without linking to them from inside the app.

## 8. Troubleshooting

| Symptom | Cause |
|---|---|
| App opens the marketing homepage | Built with `npm run build` instead of `build:mobile` |
| Blank screen | `frontend/build` missing — run the web build, then `npx cap sync ios` |
| Every request fails / CORS errors | `REACT_APP_API_URL` not set at build time, or the server's `FRONTEND_URL` is set but the deploy predates the native CORS origins |
| Content under the notch | `is-native` class missing — check `initNativeShell()` runs in `src/index.js` |
| Page zooms when typing | An input with a font under 16px; the native CSS in `index.css` handles this |
| Pod install fails | `cd ios/App && pod install --repo-update` |
